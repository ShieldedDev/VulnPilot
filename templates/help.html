What is OWASP Top 10?

The OWASP Top 10 is a standard awareness document for developers and security professionals. It represents a broad consensus about the most critical security risks to web applications. Published by the Open Web Application Security Project (OWASP), it is widely adopted as a de facto standard for web application security.

Our scanner tests your target against all OWASP Top 10 categories using automated payload testing, header analysis, configuration checks, and heuristic detection.

A01 Broken Access Control

Access control enforces policy such that users cannot act outside of their intended permissions. Failures typically lead to unauthorized information disclosure, modification, or destruction of all data or performing business functions outside the user's limits.

Common Issues:

  • Insecure Direct Object References (IDOR)
  • Missing function-level access control
  • Directory traversal
  • Admin panel accessible without auth
How Our Scanner Detects It: Tests IDOR patterns against common endpoints (/user/1, /profile/1), checks admin URLs for unauthorized access, and validates directory traversal vectors.

A02 Cryptographic Failures

Previously known as "Sensitive Data Exposure," this category focuses on failures related to cryptography which often lead to exposure of sensitive data.

Common Issues:

  • Data transmitted in cleartext (HTTP instead of HTTPS)
  • Weak cryptographic algorithms
  • Hardcoded secrets in source code
  • Improper certificate validation
How Our Scanner Detects It: Checks SSL/TLS version and configuration, validates certificates, checks for HTTP vs HTTPS, and analyzes cipher suites.

A03 Injection

Injection flaws occur when untrusted data is sent to an interpreter as part of a command or query. SQL, NoSQL, OS, and LDAP injection attacks can occur when the interpreter executes hostile data.

Types Detected:

  • XSS (Reflected) — Payload injected and reflected in response
  • SQL Injection — Error-based and blind SQLi
  • Stored XSS Indicators — Suspicious inline scripts
How Our Scanner Detects It: Sends a battery of XSS and SQLi payloads to URL parameters and form inputs. Analyzes responses for error messages, reflection, and SQL error patterns.
Example XSS Payload Tested:
<script>alert("XSS")</script>

A04 Insecure Design

A new category for 2021, focusing on risks related to design and architectural flaws. Insecure design is not the source of all other Top 10 risk categories.

How Our Scanner Detects It: Identifies patterns suggesting insecure design such as predictable resource locations, missing rate limiting indicators, and absence of security controls.

A05 Security Misconfiguration

Security misconfiguration is the most commonly seen issue. This is commonly a result of insecure default configurations, incomplete configurations, open cloud storage, misconfigured HTTP headers, or verbose error messages.

Common Issues:

  • Missing security headers (CSP, HSTS, X-Frame-Options)
  • Default credentials unchanged
  • Sensitive files exposed (phpinfo.php, .env, .git)
  • Directory listing enabled
  • Verbose error messages exposing stack traces
How Our Scanner Detects It: Inspects all HTTP response headers for missing or misconfigured security headers, tests for exposed sensitive paths, and checks for information disclosure.

A06 Vulnerable & Outdated Components

Components such as libraries, frameworks, and other software modules run with the same privileges as the application. If a vulnerable component is exploited, it can facilitate serious data loss or server takeover.

How Our Scanner Detects It: Technology fingerprinting via HTTP headers, HTML source analysis, and response patterns to identify software versions for known vulnerability correlation.

A07 Identification & Authentication Failures

Application functions related to authentication and session management are often implemented incorrectly, allowing attackers to compromise passwords, keys, or session tokens.

Common Issues:

  • Permits brute force or automated attacks
  • Uses weak or well-known passwords
  • Has weak or ineffective credential recovery
  • Exposes session IDs in URLs
  • Doesn't invalidate sessions after logout
How Our Scanner Detects It: Checks login endpoints for account lockout mechanisms, CAPTCHA presence, and rate limiting indicators.

A08 Software & Data Integrity Failures

A new category for 2021, focusing on making assumptions related to software updates, critical data, and CI/CD pipelines without verifying integrity.

How Our Scanner Detects It: Checks for Subresource Integrity (SRI) attributes on external scripts and stylesheets.

A09 Security Logging & Monitoring Failures

Without logging and monitoring, breaches cannot be detected. Insufficient logging, detection, monitoring, and active response can occur at any time.

How Our Scanner Detects It: Checks for verbose error pages that expose stack traces, log files accessible via URL, and error message information disclosure.

A10 Server-Side Request Forgery (SSRF)

SSRF flaws occur whenever a web application is fetching a remote resource without validating the user-supplied URL. It allows an attacker to coerce the application to send a crafted request to an unexpected destination.

How Our Scanner Detects It: Injects SSRF payloads into URL parameters, checks for webhook and callback endpoints, and tests file inclusion vectors.
